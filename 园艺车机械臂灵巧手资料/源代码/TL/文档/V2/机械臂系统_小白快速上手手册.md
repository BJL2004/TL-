## 0. 30 秒看懂这套系统

**硬件**（一句话版）：

| 部件 | 干什么的 |
|---|---|
| 机械臂（6 个关节 J1~J6） | 干活的"手"，能抓种子、叉花篮 |
| 腕上相机（D435） | 机械臂的"眼睛"，用来认盆上贴的黑白方块码（ArUco 码） |
| 灵巧手 / 叉子 | 末端工具：种子流程用灵巧手，修剪流程用 U 形叉 |
| Nano 小电脑 | "大脑"，上面跑所有程序 |
| 小车 / 上位机 | 通过 **MQTT** 给机械臂发命令（比如"给 A1-05 放种子"） |

**软件怎么协作**：

```
小车发命令 ──MQTT──▶ Nano 上的"运行程序" ──▶ 驱动机械臂做动作
                        ▲                      │
                        └── MQTT 反馈结果 ◀────┘

"示教程序"是另一个角色：你手动拖着机械臂走一遍，它把位置记到 YAML 文件；
"运行程序"干活时就照着这份 YAML 走。
```

**两套作业**：

1. **种子作业**：从固定点抓一粒种子 → 走到花盆处识别码 → 放进盆里 → 回待机位。
2. **修剪作业**：把花篮用叉子叉起来 → 搬到修剪位（等小车剪根）→ 再放回原处。

## 1. 先认识"编号"（看懂命令里的 A1-05）

- 整个架子共 **192 个盆** = 8 排 × 每排 24 个；
- 排的名字：**A1 A2 A3 A4 B1 B2 B3 B4**；盆的总编号 1~192。

| 排 | 盆号范围 | 排 | 盆号范围 |
|---|---|---|---|
| A1 | 1 ~ 24 | B1 | 97 ~ 120 |
| A2 | 25 ~ 48 | B2 | 121 ~ 144 |
| A3 | 49 ~ 72 | B3 | 145 ~ 168 |
| A4 | 73 ~ 96 | B4 | 169 ~ 192 |

- 命令里用 **"排-序号"** 的写法：`A1-05` = A1 排第 5 个 = 总编号第 5 号盆。
  换算公式：排 = （盆号−1）÷24；A2-06 = 24+6 = 盆号 30。
- **ArUco 码 ID ↔ 编号**：**编号 = ID + 1**（ID 0..191 ↔ 编号 1..192）。
  例：看到 **ID34** → 编号 35 → 减 1 除以 24 得排（A2）、余数+1 得第几格（第 11 格）→ **A2-11**。
  （A3 排的码是倒贴的，属特例、已由程序自动换算，见第 11.1 节。）
- **上排 / 下排**：A1、A4、B1、B4 这四排位置低，叫**下排**（新版程序会自动先去做一个"观测位"步骤）；A2、A3、B2、B3 是**上排**。
- **识别位置规则（上排检测位 / 下排检测位）**：**上排盆**（A2/A3/B2/B3）没有单独的观测位——运行时**直接去该盆的检索位**识别码；**下排盆**（A1/A4/B1/B4）先去**对应侧的下排观测位**识别（教时按 `d` 记录、`g` 验证），识别完再回该盆检索位干活。

## 2. 名词小词典（小白版）

| 名词 | 人话解释 |
|---|---|
| 示教 | 你用手拖着机械臂走到某个位置、按下按键把位置"记下来"。机械臂不会自己知道盆在哪，必须先教 |
| 运行 | 程序照着教好的位置自动干活 |
| 检索位（search pose） | 某盆干活时的"站位"：能看到这盆的码、能伸过去操作（按 B 时记录） |
| 落种接近位(A) / 落种释放位(P) | 种子流程里"手先靠近盆口上方" / "真正把种子放进盆里"的两个位置（教一次每盆） |
| 下排观测位 | 下排盆专用的"看码位置"，分 A / B 两侧各记一个（只有新版有） |
| 待机（观测）位 | 没活干时站着待命的位置（启动、作业结束回到这里；2026-10-07 起统一为种球默认位 `-23.246, -14.220, 53.738, 4.389, 26.746, -3.532`）；**不用于识别码**，别和下排观测位混淆 |
| W 载运点 / T 暂放位 | 叉子搬运花篮路上的两个中转点：**上排用一对（教一次）；下排（A1/A4/B1/B4）用另一对**（2026-10-08 起，教下排盆时按 W/T 自动存下排专用） |
| 修剪位 1 / 2 | 两个**写死在程序里**的固定位置，不用教（花篮最终放在那里等剪根） |
| ArUco 码 | 盆上贴的黑白方块码，相机认它来识别盆 |
| ServoJ | 机械臂平滑运动的执行方式；日志里 `streaming / ServoJ points` 都是它在工作 |
| MQTT | 消息通道：命令走 `node/arm/01/down`，反馈走 `node/arm/01/up` |
| retCode | 反馈里的结果码：**0**=成功、**1**=已接受/开始、**2**=位置被占/忙、**3**=失败（含识别不到） |
| targetId | 命令里要操作的盆，如 `"A1-05"` |

## 3. 怎样远程进入 Nano

Nano 就是一台带 Ubuntu 的小电脑。你有两种方式"进去"：

### 方式 A：图形远程桌面（NoMachine）—— 日常推荐

1. 在**电脑**上打开 NoMachine（桌面有图标）；
2. 新建连接（New connection），填 **Nano 的 IP 地址**（以前连过的话，历史列表里就有）；
3. 输入 Nano 的用户名（`nvidia`）和密码；
4. 进入 Ubuntu 图形桌面后，在桌面**右键 → Open Terminal** 打开终端，就能敲本文档里的所有命令。

### 方式 B：SSH 命令行 —— 只敲命令时用（快、省资源）

在 Windows 的"终端 / PowerShell / Git Bash"里输入：

```bash
ssh nvidia@<Nano的IP>
# 例如：ssh nvidia@192.168.1.50
```

- 第一次连接会问 `yes/no` → 输 `yes`；
- 然后输密码（**输入时屏幕不显示任何字符，是正常的**）；
- 看到提示符变成 `nvidia@ubuntu:~$` 就成功了。

### Nano 的 IP 从哪看？

- 能在 Nano 上操作时，打开终端执行 `hostname -I`，输出的第一串就是（形如 `192.168.x.x`）；
- 或者看路由器后台的"已连接设备"列表；
- ⚠ 换网络/重启路由器后 IP 可能变化，连不上先查 IP。

### 连不上排查

| 现象 | 先查什么 |
|---|---|
| 一直连不上 | 电脑和 Nano 是不是同一个网络（同一个 WiFi/交换机）？ |
| 之前能连现在不行 | Nano 的 IP 变了（重新 `hostname -I`）？Nano 关机了？ |
| SSH 提示密码错误 | 大小写/输入法（密码里的符号要在英文输入法下敲） |

## 7. 程序一【种子示教】怎么用

**干什么**：把"每个盆的放种位置"教给机械臂，存进 `~/tl_mock_pick_place/basket_aruco.yaml`。

```bash
# 只教上排盆 → 推荐老版（⚠️ A3 排例外：A3 码贴反，教它要用新版，见第 11.1 节）：
bash ~/Desktop/TL/scripts/teach_seed.sh
# 要教下排盆（要先记录观测位）→ 必须用新版：
bash ~/Desktop/TL_lowerobs_test/scripts/teach_seed.sh
```

启动后：机械臂自动去 A 侧起始位；电脑上弹出相机画面（能看到识别到的码）。

**按键人话解释**：

| 按键 | 意思 | 会自己动吗 | 两版差异 |
|---|---|---|---|
| 数字键 / `c` | 打盆编号 / 清空重输 | 不动 | 相同 |
| `B` | **选定这盆**：锁定当前看到的码 + 记住现在站的位置（检索位） | 不动 | 相同 |
| `A` | 记"落种接近位"（手先靠近盆口上方） | 不动 | 相同 |
| `P` | 记"落种释放位"（手到达放种子的位置） | 不动 | 相同 |
| `F / I / L / T` | 叉子相关的备用记录键 | 不动 | 相同 |
| `R` | 回到当前盆的检索位（一次自动运动，等它走完） | ✅ 会 | 相同 |
| `Q` | 退出程序 | 不动 | 相同 |
| `v / d / g` | 切侧 / 记录下排观测位 / 回位验证 | v、g 会动 | **只有新版有**（老版没有"记录下排观测位"的功能） |

**标准操作（每盆 5 步）**：

```
① 按住臂上的拖拽钮，把臂拖到"能看清目标盆的码"的位置
② 输编号 → 按 B    （⚠ 手先松、臂停稳 1~2 秒再按，否则报"看不清/样本不稳"）
③ 拖到落种接近位 → 按 A
④ 拖到落种释放位 → 按 P
⑤ 按 R 回到检索位 → 拖向下一盆，重复 ①~⑤
```

**下排盆（A1/A4/B1/B4）额外前置（用新版）**：先各教一次两侧观测位——

```
拖到能看清 A 区下排码处 → 停稳 → 按 d（打印 side=A 就对）→ 按 g 验证能回位
按 v 切到 B 侧 → 拖到位 → 停稳 → 按 d → 按 g 验证
```

> 每次按完 `d`，**看一眼打印的 side=A 还是 B**，别记反。

## 8. 程序二【叉子示教】怎么用

**干什么**：教"每个盆的叉取位置（F/I/L）"+ 两个全局点（W/T）+ 待机位（O）+ 下排观测位，存进 `~/tl_fork_teach/fork_basket_teach.yaml`。

```bash
# 建议统一用新版：
bash ~/Desktop/TL_lowerobs_test/scripts/teach_fork.sh
# 老版（没有 v/d/g 下排观测位那组键，其余操作相同）：
bash ~/Desktop/TL/scripts/teach_fork.sh
```

启动后：**不动臂**；只有 `v / g / R` 会自己动，其它全靠手拖。

### 第 0 步（一次性，做一遍就行）

1. 按 `O` → 臂去**待机位**（2026-10-07 起为种球默认位 `[-23.246, …]`）并记录（这就是运行端"启动/干完活回来"的位置）；
2. 下排观测位（要跑下排盆之前必须做）：确认当前侧是 A（按 `v` 切换，看打印 `Current side: A`）→ 拖到能看清 A 区下排码处 → 停稳 → 按 `d` → 按 `g` 验证；**B 侧不必记录**（运行端自动按 A 侧 +180° 推导，手动记录优先）。

### 教叉子下排盆（A1/A4/B1/B4）的小流程

```
① （第一次教下排前）确认第 0 步已完成（待机位 + A 侧观测位）
② 瞄准：按 g 到下排观测位附近 → 按住拖拽钮微调到"能看清这盆的码"的位置
③ 输编号（A1=1~24，A4=73~96，B1=97~120，B4=169~192）→ 停稳 1~2 秒按 B
   （按 B 的位置会记成该盆检索位——尽量选在盆正前方、方便伸叉的位置）
④ 拖到叉接近位按 F → 水平插入按 I → 竖直抬起按 L
   ✳ 第一盆下排要接着教 W/T：拖到"下排专用高位载运点"按 W → 拖到"下排专用暂放位"按 T
     （当前选中的是下排盆 → 自动存成"下排专用"槽位，上排原有的不受影响；2026-10-08 起）
⑤ 按 R 回检索位（等 "Returned: max joint error=…"）→ 换下一盆重复 ②~⑤
   （第 2 盆起：输编号 → B → F → I → L → R，W/T 不用再按）
```

> B 区盆小技巧：教 B 区之前按 `v` 切到 B 侧起始位，再往前拖到目标盆；教完想回 A 侧再按一次 `v`。
> 运行时（trim_pick）：A 区下排去"下排观测位 A"识别（日志 `YAML lower_observation_pose_a.`）；B 区下排去自动推导的 B 侧位（日志 `derived … rotated 180 deg`）。

**按键人话解释**：

| 按键 | 意思 |
|---|---|
| 数字 / `c` / `B` | 输编号 / 清空 / 选定这盆（记住站位） |
| `F` | 记"叉子接近位"（叉尖对准盆口前方） |
| `I` | 记"水平插入位"（叉子插进盆沿下方；会检查你是不是水平插的） |
| `L` | 记"竖直抬起位"（叉子把盆微微抬离；会检查是不是竖直抬的） |
| `W` | 记"高位载运点"（举着花篮走路的高点）——**全局教一次**；若当前选中的是**下排盆**，会自动存成"**下排专用**" |
| `T` | 记"暂放位"（搬运链上花篮的中转点）——**全局教一次**；下排盆同理存成"**下排专用**" |
| `O` | 去**待机位**并记录（已统一为种球默认位 `[-23.246, …]`；运行程序启动/干完活都回这里，2026-10-07 起） |
| `v / d / g` | 切侧 / 记录下排观测位 / 回位验证（**只有新版有**） |
| `R` | 回当前盆检索位（等看到 `Returned: max joint error=…` 才算走完） |
| `Q` | 退出 |

**三个"位"别搞混**（按 `O` 去的是种球默认位，是正常设计）：

| 键 | 去的位置 | 干什么用 |
|---|---|---|
| `O` | **待机位** = 种球默认位 `[-23.246, -14.220, 53.738, 4.389, 26.746, -3.532]` | 启动/收工回位、刷新待机记录；**不是"看花篮"的位置**（2026-10-07 起统一） |
| `v` | **A / B 侧起始位** `-83.668… / 96.332…`（J1±180°） | 教花篮的起点站位——**这就是老的"观测位"**；注意当前侧是 A 时第一下 `v` 会先去 B 侧，再按一下才回 A 侧 |
| `g` | **下排观测位**（当前侧；`d` 记录） | 看下排盆（A1/A4/B1/B4）的码；上排盆不看这里，直接去该盆检索位 |

**标准操作**：

```
第一盆（必须一次教完 W 和 T；**下排盆的第一盆同理**——那时按 W/T 会自动存成下排专用那对）：
① 输编号 → B → 拖到叉接近位按 F → 拖到水平插入按 I → 拖到竖直抬起按 L
② 拖到高位载运点按 W → 拖到暂放位按 T → 按 R 回检索位
以后每盆：
输编号 → B → F → I → L → R      （W/T 不用再按；重按会按"当前盆的排"覆盖上排或下排对应那一对，别误按！）
```

**被拒绝不慌**：按 I / L 时报 "horizontal travel is only…" 之类，是程序发现你拖得不够直/不够远，重新拖到位再按即可（阈值：水平 ≥20mm、竖直 ≥30mm、漂移 ≤60mm、姿态变化 ≤25°）。

## 10. 程序四【叉子运行】怎么用

```bash
# 建议统一用新版：
bash ~/Desktop/TL_lowerobs_test/scripts/run_fork_mqtt.sh
```

启动后（没有未完搬运时）先回到**待机位**（2026-10-07 起与种子程序统一：`-23.246, -14.220, 53.738, 4.389, 26.746, -3.532`），然后等命令：

| 命令 | 效果 |
|---|---|
| `{"cmd":"trim_pick","targetId":"A2-06"}` | 叉起花篮 → 搬到**修剪位2**停住（等小车剪根） |
| `{"cmd":"trim_place","targetId":"A2-06"}` | 从修剪位搬回、放回原处 → 回待机位 |
| `{"cmd":"estop"}` | 程序级急停（之后所有命令会被拒绝，要**重启程序**才解除；真正断电请按物理急停） |

**反馈**：`trim_pick` 先回 `retCode:1`（已开始），干完回 `retCode:0`（成功）；放回同理。如果收到 `retCode:2` + `a basket is already held; send trim_place first`，说明"上次搬运没结束"（处理见下👇）。

**一直检测不到码怎么办？**——识别位会等约 10 秒，失败直接回 `retCode:3`（`marker number N was not stable at the detection pose`），并且**机械臂会自动回到待机位**（与种子流程一致，2026-10-07 起）；排查原因（码被挡 / 光照 / 点位偏移）后，**重新发一条同样的 `trim_pick`** 即可重试，不需要做别的操作。

**状态文件（小白也要懂的一条）**：

- 运行程序把"正在搬的花篮"记在 `~/tl_fork_teach/active_transfer.yaml`；
- 正常 **trim_pick → trim_place 走完整圈后，这个文件会自动消失**；
- 如果搬运/回位**半路被 Ctrl+C 打断**，文件会残留——下次启动就会看到：

```
Active fork transfer state found: basket number=30, phase=hold1. …
Startup: a basket is still held (active fork state); the arm will NOT auto-move. …
```

意思 = "记账本里还有一单没完成"，程序出于安全**拒绝新任务**。

**怎么处理（先肉眼看叉子上有没有花篮！）**：

- 叉是空的（多数情况）→ 清掉记账本即可：
  ```bash
  cat ~/tl_fork_teach/active_transfer.yaml     # 看一眼
  rm ~/tl_fork_teach/active_transfer.yaml      # 删除（不影响示教数据）
  ```
- 真叉着花篮 → 别删！重启运行程序后发 `{"cmd":"trim_place","targetId":"<对应盆>"}`，让它走完返回自动放回。

### 18.3 改文件 ↔ 哪个脚本生效 ↔ 要不要编译（总表）

**先记结论：本项目（`TL` 和 `TL_lowerobs_test` 里你日常用的所有程序）改任何文件都【不需要编译】。**
原因：4 个主脚本启动时把 `src` 目录排在最前面塞进 `PYTHONPATH`，再用 `python3 -m` 直接加载 `.py` 源码——Python 每次运行都重新读取源码文件，所以改完只要"重启对应脚本"就生效。（`.pyc` 缓存会自动刷新，不用管。）

| 你改的文件 | 由哪个脚本加载 / 生效于 | 要编译吗 | 怎么生效 |
|---|---|---|---|
| `src/tl_hand_deploy/tl_hand_deploy/aruco_basket_teach.py`（种子示教） | `scripts/teach_seed.sh` | ❌ 不用 | 重启 `teach_seed.sh` |
| `src/tl_hand/tl_hand/mock_pick_place.py`（种子运行） | `scripts/run_seed_mqtt.sh` | ❌ 不用 | 重启 `run_seed_mqtt.sh` |
| `src/tl_fork_teach/tl_fork_teach/fork_basket_teach.py`（叉子示教，也是**叉子运行的基类**） | `scripts/teach_fork.sh`，**同时影响** `scripts/run_fork_mqtt.sh` | ❌ 不用 | 用到哪个重启哪个（只改了示教相关就只重启示教） |
| `src/tl_fork_teach/tl_fork_teach/fork_basket_cycle.py`（搬运核心 / 修剪位常量） | `scripts/run_fork_mqtt.sh`（经 `fork_trim_mqtt` 继承） | ❌ 不用 | 重启 `run_fork_mqtt.sh` |
| `src/tl_fork_teach/tl_fork_teach/fork_trim_mqtt.py`（叉子运行入口） | `scripts/run_fork_mqtt.sh` | ❌ 不用 | 重启 `run_fork_mqtt.sh` |
| `src/tl_hand/tl_hand/mqtt_protocol.py`（MQTT 协议） | **两个运行程序都用到**：`run_seed_mqtt.sh`、`run_fork_mqtt.sh` | ❌ 不用 | 用到哪个重启哪个 |
| `scripts/*.sh`（改参数、改路径） | 它自己 | ❌ 不用 | 重新执行该脚本 |
| `scripts/list_taught.py`（查点工具） | `scripts/list_taught.sh` | ❌ 不用 | 直接再跑一次 |
| 数据 YAML（示教数据 / 作业状态文件） | 运行程序启动时读取 | ❌ 不用 | 重启运行程序（状态文件另见第 10 节） |
| **驱动包** `~/Desktop/tl_robot_ros2_py-arm/src/...`（`tl_driver` 节点、消息/服务定义等） | 驱动：`ros2 launch tl_driver …` | ✅ **要** | 见下表下方 |

**唯一需要编译的情况——改了驱动包**（`tl_driver` 节点、消息/服务定义 `.msg/.srv` 等）：

```bash
cd ~/Desktop/tl_robot_ros2_py-arm
colcon build                                  # 全编最稳；或只编改动的：colcon build --packages-select tl_driver
source install/setup.bash
# 然后：重启驱动终端，再重启用到它的程序（示教/运行程序）
```

**判断口诀**：

- 改的东西在 `~/Desktop/TL_lowerobs_test` 或 `~/Desktop/TL` 里 → **不用编译**，重启脚本；
- 改的东西在 `~/Desktop/tl_robot_ros2_py-arm`（驱动包）里 → **要编译**（`colcon build`）；
- 改的是"消息 / 服务定义"（`.msg/.srv`，一般在驱动包里）→ **一定要编译**，而且编译后所有用到它的程序都要重启。

**小众例外**：老版目录里个别旧脚本（早年那批用 `ros2 launch / ros2 run` 启动"安装包"的，比如 `run_fixed_pick_mqtt.sh` 一类）走的是编译产物，改源码后要 `colcon build` 才生效。你现在日常用的 4 个主脚本都不是这种方式——**拿不准时看一眼脚本里有没有 `python3 -m`：有，就是直读源码，不用编译**：

```bash
grep -n "python3 -m\|PYTHONPATH" scripts/*.sh
```

### 18.4 标准开发流程（5 步）

```
① 在电脑上改代码（推荐 VS Code 打开 TL_lowerobs_test 文件夹）
② 传到 Nano 对应位置（第 15 节）
③ 在 Nano 上做语法检查：  python3 -m py_compile 你改的文件.py
   （没输出=语法没问题；报错会指出第几行，先修语法）
④ 空载测试：不放手爪/花篮，跑一遍示教程序或发一条命令，看打印
⑤ 测试稳定后，才考虑合并回 TL 稳定版
```

1. VS Code 装插件 **Remote - SSH**；
2. 左下角绿色按钮 → Connect to Host → 输入 `nvidia@<Nano的IP>`；
3. 之后直接打开 Nano 上的文件夹（如 `/home/nvidia/Desktop/TL_lowerobs_test`），**像编辑本地文件一样改代码，保存就直接保存到 Nano**，不用来回传。

## 19. 小白常见问题速查表

| 现象 / 提示 | 什么意思 | 怎么办 |
|---|---|---|
| `Permission denied` | 脚本没有执行权限（从 Windows 拷过去常见） | `chmod +x …/scripts/*.sh`，或始终用 `bash 脚本` 方式启动 |
| 按 B 报 `not visible / not enough stable samples` | 手没停稳或码看不清 | 松开手、停稳 1~2 秒，再按一次 B |
| 按 d 报 `/tcp_pose is stale` | 同上，臂没停稳 | 等 1~2 秒再按 d |
| `a basket is already held` / `Active fork transfer state found` | 叉子有"未完成搬运"的记账 | 见第 10 节：空的就 `rm` 记账文件；真叉着花篮就发 `trim_place` |
| B 区下排（B1/B4）叉取会去哪个观测位？ | 程序**自动按盆号**选侧（97–192 号盆 → B 侧）；B 侧**没有单独记录时自动 = A 侧记录把 J1 加 180°**（2026-10-07 起；场地 A/B 精确对称，实测两侧起始位 J1 正好差 180.000°） | 看到日志 `derived from the A-side record rotated 180 deg` 就是走了自动推导；你手动记录过 B 则以记录为准 |
| `lower-row observation pose for side A is not recorded`（retCode 3） | **A 侧**下排观测位还没记录（B 侧自 2026-10-07 起会自动推导，不再报错） | 到示教程序：按 v 切到 A 侧 → 拖到能看清 A1/A4 码处 → 停稳 → 按 d → 按 g 验证；核实用 `list_taught.sh` 看 [全局] 行 |
| `marker number N was not stable at the detection pose`（retCode 3） | 叉取时在识别位等了约 10 秒都没能稳定看到码（被挡 / 光照 / 点位偏移；`got 0 samples` = 一帧都没看到） | 程序会**自动回待机位**（2026-10-07 起，对齐种子流程）；排查后**重新发一条同样的 `trim_pick`** 重试 |
| `basket number X is not taught`（retCode 3） | 这个盆没做过**叉子示教**（注意：种子教过 ≠ 叉子教过，两套流程各自教各自的） | 到叉子示教程序把该盆教一遍（B→F→I→L→R）；或先换一个已教过的盆测试 |
| "默认观测位（−23.246…）"和"下排观测位"是一回事吗？ | **不是**：默认观测位=待命站位（启动/收工用，**不看码**）；下排观测位=专门看下排盆码的识别位置（v→拖→d 记录）；上排盆则连观测位都不去（**直接检索位**） | 三者数值、用途都不同；`seed A1-01`/`trim_pick A1-01` 去"下排观测位 A"，`seed A2-01` 去"A2-01 检索位"，谁都不去默认观测位（它只在出发前/收工后出现） |
| 下次示教怎么从待机位回到下排观测位？ | 按 `g`——臂**自动**去"当前侧"已记录的观测位（不用手拖）；想先回待机位按 `O` | 观测位只记一次、长期有效；要改位置就拖到位再按 `d` 覆盖。B 侧没单独记录时 `g` 会提示未记录——直接按 `v` 切侧后手拖即可（运行端会自动推导 B 侧） |
| 下排盆要不要教 W / T？ | **要教一对下排专用的**（2026-10-08 起）：教下排第一盆时按 W、T 就会自动存成"下排专用"（上排那对不受影响）；之后运行下排盆自动用下排那对 | 还没教下排那对之前：运行下排盆会沿用上排那对并打印 `WARNING: lower-row … not taught`；下排 L→W 段无沿途碰撞检测，首次仍建议"空盆 + 降速"（`--servoj-speed-deg-s 10`）试跑确认 |
| 输入 A3-08，机械臂却跑到 A3 排**后面**去了（不在前面） | A3 排的 ArUco 码**贴反了**（本该 ID48→ID71，实际贴成 ID71→ID48）；程序按码定位，于是去了码所在的后排位置 | 已修正：4 个脚本内置 `--reversed-rows A3`（输入位置号自动换成该格实际贴的码）。已教 A3 盆的新命令见第 11.1 节（**A3-18 / A3-17 / A3-11**）；补教 A3-08 / A3-14 直接用新版教（输入 56/62 就对了）。**A3 的教与跑都用新版**，老版没有修正 |
| 按 `O` 为什么去的是"抓种子默认位"，不是去看花篮？ | 设计如此：待机位（`O`）自 2026-10-07 起统一为种球默认位 `[-23.246, …]`，只管启动/收工回位，**不看码** | 看花篮用别的键：去 **A/B 起始位**按 `v`（`-83.668… / 96.332…`，即老观测位）；看**下排盆**按 `g`（先 `d` 记录）；**上排盆**直接去该盆检索位（输编号 + `B` 选中后按 `R`） |
| ArUco 码 ID 和盆编号怎么换算？ | **编号 = ID + 1**（ID 0..191 ↔ 编号 1..192） | 例：**ID34 → 编号 35 → A2-11**（减 1 除以 24 得排、余数+1 得第几格） |
| `Command rejected/stopped: … rcl node's context is invalid` | 你在动作**没走完**时按了 Ctrl+C，程序被关了 | 重启程序重做即可；下次等动作走完再退出 |
| `Returning with N direct ServoJ points.` | **正常**：一次自动运动开始了（约 N÷100 秒） | 等它出现完成打印 `Returned: max joint error=… deg` |
| `accepted=False, convention=intrinsic_xyz` | 标定文件的"验收标记"（正常启动信息） | 不用管：脚本带了 `--allow-rejected`，会继续用 |
| 一堆 SciPy / NumPy `UserWarning` | 环境版本提示 | 无视，不影响 |
| 识别不到码（`retCode 3`） | 相机看不清盆上的码 | 检查码是否贴平、是否被遮挡、距离/光线是否合适；换个角度重试 |
| 机械臂完全不动 | 驱动没起 / 程序没在等命令 / 起了两个程序 | 先看驱动终端；再确认运行程序打印了 `MQTT connected`；检查没有开第二个程序 |
| MQTT 连不上（运行程序卡住不发反馈） | 网络或账号问题 | 检查 Nano 能上网；账号密码是否正确；重启运行程序 |
| `bash: $'\r': command not found` | 脚本被 Windows 编辑器改过换行符 | `sed -i 's/\r$//' 脚本.sh` |
| 示教窗口按键没反应 | 可能是相机帧或状态短暂卡顿 | 等几秒；持续卡死记录日志反馈 |
