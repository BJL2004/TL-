# 独立 U 型叉子花篮示教说明

`tl_fork_teach` 是 TL_Handback 中独立的叉子示教包。它不属于灵巧手控制流程，也不调用灵巧手服务。

## 示教前

1. U 型叉子已经刚性安装在 tool0 上；
2. D435 已连接并且只有一个程序占用相机；
3. ArUco 黑色边长与 `--marker-length-m` 一致，默认是 58 mm；
4. 天链驱动已经启动，`/joint_states` 和 `/tcp_pose` 正常；
5. 使用与当前相机安装状态对应的手眼标定文件。

## 运动语义

记录的 `T_marker_tool0` 表示：在 ArUco 标记坐标系下，tool0 的位置和姿态。程序先冻结标记在基座下的位姿，再把当前拖动到的 tool0 位姿转换为 marker-relative 数据。以后花篮整体平移时，可以用同一组相对位姿重建叉子目标。

## 文件隔离

本程序默认写入 `~/tl_fork_teach/fork_basket_teach.yaml`，不写灵巧手工程的 YAML。保存时先把当前文件复制到 `~/tl_fork_teach/archive/`，再使用临时文件替换主文件，避免进程中断留下半个 YAML。

## 正确动作模型

U 型叉子叉取花篮时，应尽量保持叉子姿态不变，并拆成三个主要方向明确的动作：

1. `fork_approach -> fork_insert`：保持高度，水平插入；
2. `fork_insert -> fork_lift`：保持 XY，竖直向上抬升；
3. `fork_lift -> fork_transfer_pose`：到达固定临时持篮位；过程中可先抬高、再水平移动、最后按需要上下调整，但不能改变叉子姿态。

程序会拒绝顺序错误、明显斜插、斜抬、转运中降得过多或姿态变化过大的记录。默认容差是非主运动方向 20 mm、姿态 10 度，可以通过命令行参数调整。

`T` 只保存固定临时持篮位，不会自动抬升或回放。正确操作是先手动竖直抬升并按 `L`，再把叉子连同花篮移动到固定临时位并按 `T`。真正自动执行时，花篮始终留在叉子上，直到返回原位并完成抽叉。

按 `R` 会返回当前花篮的搜索/检测位，释放 ServoJ，并清空当前花篮选择。看到终端提示 `Ready for the next basket` 后，手动平移到下一篮，按 `1..6` 选择编号，再按 `B` 开始下一组示教。这样下一组数据不会误写到上一篮。

## 与执行程序的关系

示教输出的结构兼容 U 型叉子执行程序需要的字段，但示教程序本身不会叉取花篮，也不会控制灵巧手。只有按 `R` 且启动时传入 `--execute` 才会返回搜索位。完成示教后，应先检查 YAML 中每个 marker 是否都有 `search_pose`、`fork_approach`、`fork_insert`、`fork_lift` 和全局 `fork_transfer_pose`，再运行 `tl_fork_basket_cycle`。

执行节点的固定顺序是：检索位重新定位 -> 接近 -> 水平插入 -> 竖直抬升 -> 抬高后水平转运 -> 固定临时位；返回时反向执行，先回到原花篮上方，再下降、抽叉并回检索位。执行节点把原始 `T_base_marker` 保存到单独的 `active_transfer.yaml`，不会依赖花篮在临时位继续可见。
