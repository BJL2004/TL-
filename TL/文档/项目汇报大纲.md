## 一、项目概述（8 min）

### 1.1 一句话介绍
"在一台移动小车上，用天链 TCB605 机械臂 + D435 相机 + ROH-LiteS001 灵巧手 + U 型叉子，通过 MQTT 远程协议完成 **两个农业任务**：给 192 个花盆**放种子**、把花盆**叉到修剪位剪根后放回**。"

### 1.2 任务与规模
| 任务 | MQTT 命令 | 动作 |
|---|---|---|
| 放种子 | `seed` / `seed_place` | 固定点取种 → 识码定位花盆 → 放置 → 回位 |
| 叉花篮修剪 | `trim_pick` / `trim_place` | 叉起花篮 → 高位搬运 → 修剪位两段剪根 → 放回 |
| 急停 | `estop` | 立即停止（锁存，重启节点解除）|

- 花盆布局：**A/B 两区 × 4 排 × 24 盆 = 192**（A1-01…B4-24 → 1…192）
- 每个花盆贴唯一 ArUco 码：DICT_4X4_250、ID 0~191、黑方块 54mm

### 1.3 演示素材（讲之前先播 / 展示）
- 一段完整放种视频（MQTT 发命令 → 4 条反馈 → 种子落盆）
- 一段叉花篮修剪视频

## 三、系统架构与数据流（10 min）

### 3.1 分层架构图
```
上位机（天链软件）—— 只用于本体操作：连接/使能/拖拽/点动
        │ 网口 TCP
机械臂驱动 tl_driver —— /joint_states、/tcp_pose、IK 服务、Modbus 透传
        │ ROS2
业务节点（TL_Handback）
 ├── 种子节点 tl_mock_pick_place[_headless]   （相机+灵巧手+MQTT）
 └── 叉子节点 fork_trim_mqtt                   （相机+叉子+MQTT）
        │ MQTT（公网 broker）
车端 / 上位机 / MQTTBox —— 发命令、收 4 段反馈
```

### 3.2 坐标链与标定（一句话讲清）
```
p_base = T_base_tool0 × T_tool0_camera × p_camera
         （驱动实时）    （手眼标定）      （相机内参）
```
- **手眼标定**：25-35 组棋盘格样本 → 质量门（平移 RMS≤5mm 等 14 项）→ 九点验证（XY RMS≤5mm）
- **九点验证通过前禁止灵巧手自动闭合**（安全铁律）

### 3.3 示教体系（192 盆怎么"记住"）
- 每盆 3 个姿态：检索位 `B`（码可见）→ 接近位 `A`（盆上方）→ 释放位 `P`（盆口内）
- 运行时用相机识码做**动态补偿**（花盆小范围挪动 ≤200mm 自动跟随）
- 示教要点：输入号→**B 必须看到 Selected=输入号**；P 必须比 A 低（有正落差）

### 3.4 MQTT 协议（4 段反馈时序）
```
发: {"cmd":"seed","targetId":"A2-05"}
收: seed:1 → seed:0 → seed_place:1 → seed_place:0
失败按阶段回 retCode:3；位置占用/忙 → retCode:2
```

## 四、两大任务流程（15 min）

### 4.1 放种子完整周期
```
校验（estop/忙/手状态/是否已示教）
→ 反馈1 seed:1
→ 取种：固定点→下降(final-grasp-z 218.880)→力度5闭合→抬起→回观测位
→ 反馈2 seed:0
→ 定位花盆：检索位识码→采样取中值→算偏移→动态修正 A/P
→ 反馈3 seed_place:1
→ 放置：接近位→释放位→张开→回力度1→回检索位
→ 反馈4 seed_place:0 → 回观测位
```

### 4.2 叉花篮修剪
```
trim_pick：检索位→叉接近F→插入I→提起L→高位搬运→两段式下降（先高位移动再低速降到修剪位）
          →位置1修剪→位置2修剪→叉住待命（active_transfer.yaml 记录携篮状态）
trim_place：抬到高位→搬回原盆→下降对位→抽叉→回检索位
```
- 安全保护：携篮状态存在时启动**不自动动**，必须先 trim_place

### 4.3 演示项（15 分钟章节内或放到第七节）
- MQTTBox / mosquitto 订阅 `node/arm/01/up`，现场发一条 seed
- 讲解反馈时间线（哪条是"开始动"、哪条是"取种完成"、哪条是"放置完成"）

### 5.4 踩坑记录（体现工程严谨性，选讲）
1. 示教脚本残留 `--marker-ids 0..23` 过滤 → 新码 24+ 全"识别不到"
2. 旧仓库 install 残留 → 改了代码不生效（节点加载旧包）
3. 码长默认值不统一（0.056/0.058/0.054）→ 全部统一 54mm
4. 双字典回退（4×4_50 兼容）→ 正式流程移除，只用 DICT_4X4_250

## 六、VLA 技术路线：项目规划中学习方案的优势（15 min）★ 本次汇报重点

### 6.0 先明确立场（开场就说清，避免误解）
> **本项目当前没有采用 VLA（也没有采用千问 VLA）。**
> 当前生产管线 = 手工示教 + ArUco 定位 + 确定性 ServoJ 轨迹 + MQTT 协议，
> 已实现 192 盆、双任务闭环。本章介绍的是**项目规划中评估过的 VLA/学习方案及其优势**——
> 为下一阶段的技术升级做储备。

### 6.1 基线为什么是传统示教（对比的起点）
| 优势 | 说明 |
|---|---|
| 精度可控 | 手眼标定平移 RMS 4.65mm + 九点验证（XY RMS ≤5mm）|
| 完全可解释 | 每帧动作都是确定性计算，出问题可逐环节排查 |
| 零训练数据 | 示教一次即可运行，不依赖大规模数据采集 |
| 局限 | 换臂/换场景要重做标定与示教；无法处理任务与目标的变化 |

→ 正是因为基线的这些局限，项目规划中才评估了学习方案。

### 6.2 项目文档中评估过的方案及其优势（逐个讲"优势"）

| 方案 | 类型 | **核心优势** | 在本项目的落地形态 |
|---|---|---|---|
| **ACT** | 模仿学习（动作 chunk）| ① 数据需求小（几十条示教即可）② 一次预测未来 8~32 步动作，滚动执行 ③ 不依赖语言，工程链路最短 ④ 最适合"固定俯视抓取+放置"这类连续动作任务 | 第一版学习策略：只学"取种→放种"单任务 |
| **VA**（视觉-动作）| 策略学习（任务 ID 条件化）| ① 无语言模块，算力开销小 ② 输出空间可**严格限定**为关节增量/末端相对位姿+手部意图 ③ 最容易配合本地 action_guard 安全层 ④ phase_id 条件化天然匹配 seed_pick/seed_place/trim 等阶段 | 固定流程的主力选择 |
| **pi0**（openpi）| 通用 VLA | ① 开源（Physical Intelligence openpi）② 跨本体泛化能力强 ③ 多任务 + 语言条件 ④ 社区生态成熟、参考实现多 | 中长期：远程 policy server |
| **SmolVLA** | 轻量 VLA | ① 参数量小，**可量化后边端部署**（Jetson 本地试跑）② 保留语言能力 ③ 部署门槛低于大型 VLA | 小模型试点：Jetson 本地推理验证 |
| **GR00T**（NVIDIA）| 通用/人形 VLA 平台 | ① 官方支持 **server-client 解耦部署**（模型端与机器人端分离）② 官方提供**新本体微调流程** ③ 与本项目"Jetson 控制端 + 外部 GPU 模型端"分工天然契合 | 远程推理架构的工程参考 |

### 6.3 学习方案能给项目带来什么（优势总结——培训讲透这一点）

1. **泛化**：目标位置轻微变化、物体外观变化时不用重新示教（现在的 200mm 动态补偿是几何法，学习法可以更进一步）
2. **换本体成本降低**：换机械臂/换末端时，策略只需小幅微调，而不是重做标定+取种点+全部示教
3. **多任务统一**：seed / trim 等任务可用同一策略 + 任务条件（VA 用 phase_id，VLA 用自然语言）
4. **语言接口（VLA 特有）**：支持"把 A2-05 的种子放进指定花篮"这类自然语言任务指令
5. **数据资产化**：运行与示教数据可沉淀为训练集（项目已有 192 盆示教数据的天然基础）

### 6.4 千问 VLA 的定位：对比参考，本项目未采用

**客观介绍**（2026 年 6 月发布，阿里千问）：
- **Qwen-RobotManip**（VLA 操作模型）：**80 维统一动作表征**（跨硬件"肢体语言"）、基于画面**相对位置**操作（不依赖绝对坐标）、**38,000+ 小时**开源语料预训练、RoboChallenge Table30 v1 真机测评前两名
- 同系列：Qwen-RobotNav（导航）、Qwen-RobotWorld（世界模型）、Qwen-RobotClaw（智能体框架）

**本项目没有采用它的原因**（讲清楚，避免"为什么不用最好的"疑问）：
| # | 原因 | 说明 |
|---|---|---|
| 1 | 部署规模 | 大型模型需要 GPU 服务器，车端只有 Jetson → 必须走"远程 policy server"，工程链路更长 |
| 2 | 接口适配量 | 80 维统一动作表征要写适配层转成 TCB605 关节/ServoJ + 灵巧手 6 指接口，工作量大于 ACT/VA |
| 3 | 项目阶段 | 当前阶段目标是把传统基线做扎实（192 盆、双任务已闭环）；学习化按"ACT/VA → 受限多任务 → VLA"渐进，直接上完整 VLA 风险高 |
| 4 | 数据准备 | VLA 微调需规范采集真机数据（时间戳对齐、episode 化），项目刚开始具备该基础 |

**值得长期跟踪的点**：它的"统一动作表征 + 相对位置"思路，恰好命中本项目"换新机械臂后标定/取种点/示教全部重做"的痛点——作为未来技术评估方向保留。

### 6.5 横向对比表（突出优势与本项目现状）

| 方案 | 类型 | 核心优势 | 落地形态 | 本项目现状 |
|---|---|---|---|---|
| **ACT** | 模仿学习 | 数据需求小、链路最短、适合连续动作 | Jetson 本地 | **第一版候选** |
| **VA** | 视觉-动作 | 输出严格受限、最易配合安全层 | Jetson 本地 | **固定流程首选** |
| pi0 | 通用 VLA | 开源、跨本体、多任务+语言 | 远程服务器 | 中长期 |
| SmolVLA | 轻量 VLA | 可量化边端部署、保留语言 | Jetson 本地试点 | 试点候选 |
| GR00T | VLA 平台 | server-client 解耦、新本体微调 | 远程+本地 | 架构参考 |
| **千问 Qwen-RobotManip** | 完整 VLA | 统一动作表征、相对位置、中文生态 | 远程 GPU | **未采用，长期跟踪** |
| 传统示教（现状）| 确定性管线 | 精度可控、可解释、零数据 | Jetson 本地 | **当前生产基线** |

### 6.6 落地路线（不变的五步）
```
离线回放（只预测不执行）→ 影子模式（并行对比）→ 高位空跑（假手/限速）
→ 低速真实手（力度1保护）→ MQTT 闭环（协议不变，安全层不绕过）
```

### 6.7 安全边界（必讲）
- 模型输出必须过本地 action_guard：工作空间/速度/姿态限幅，越界即停
- 灵巧手力度仍由保护节点决定（模型只给意图 open/hold1/grasp5/release）
- 远程推理超时必须触发 hold/停止，**不能阻塞急停**
- MQTT 远程消息不能绕过本地安全状态机

## 八、风险、安全与 Q&A（7 min）

### 8.1 安全铁律（必讲）
1. 物理 E-stop 始终在手边；程序 estop 只停运动流**不是断电**
2. 运动路径上禁止站人；首次跑新姿态用慢速 + 旁观
3. **九点验证通过前禁止灵巧手自动闭合与接触抓取**
4. 换任何硬件后走"回归测试清单"，不跳步

### 8.2 Q&A 预案（预判提问）
| 可能的问题 | 回答要点 |
|---|---|
| 为什么不用 VLA 直接控制？| 当前基线精度可控、可解释、零训练数据；VLA 需要数据与算力，按"ACT/VA → 受限多任务 → VLA"渐进 |
| 千问 VLA 你们用了吗？| **没有采用**。当前是传统示教基线；千问 Qwen-RobotManip 作为长期方向对比参考（统一动作表征/相对位置思路值得跟踪），落地需远程 GPU 推理+接口适配 |
| 192 个盆要教多久？| 每盆约 1-2 分钟，熟练后 4-6 小时；支持中断续教 |
| 花盆挪动了怎么办？| 200mm 内自动动态补偿；更大要重新示教 |
| 放种不准怎么排查？| 顺序：旧记录混用 → 标定 → base_xy_bias → 机械松动（附排查表）|
| MQTT 断了会怎样？| 节点重连；远程推理模式超时必须 hold/停止（不能阻塞急停）|

### 8.3 结尾一页
```
已经做到的：192 盆布局 / 双任务 MQTT 闭环 / 手眼标定+九点验证体系 / 完整示教与动态补偿
下一步：   千问 VLA 等新方案评估 → ACT/VA 基线试点 → 数据采集规范化 → 影子模式验证
一句话：   底层稳（示教+几何），上层逐步学习化（ACT/VA → VLA）
```
