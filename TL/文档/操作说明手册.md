## 第一章 连接 Jetson（SSH）

### 1.1 准备工作
| 项 | 说明 |
|---|---|
| Jetson 的 IP | 在 Jetson 本机跑 `hostname -I` 查看（例如 `192.168.51.21`）|
| 用户名 | `nvidia` |
| 密码 | 向管理员索取（首次登录后建议修改）|
| 网络 | Windows 电脑与 Jetson 在同一网络（网线直连同网段，或同一路由器）|

### 1.2 从 Windows 连接

**方法 A：PowerShell（系统自带）**
```powershell
# 打开 PowerShell，输入：
ssh nvidia@<Jetson的IP>

# 首次连接会提示：
# The authenticity of host ... can't be established.
# Are you sure you want to continue connecting (yes/no)?  → 输入 yes 回车
# 然后输入密码（输入时不显示，输完直接回车）
```

**方法 B：MobaXterm（推荐，带文件传输面板）**
```
新建 Session → SSH → Remote host: <Jetson的IP> → Specify username: nvidia
→ OK → 输入密码 → 登录
左侧面板可直接拖拽传文件
```

**方法 C：VS Code Remote-SSH（编程/看日志方便）**
```
安装 Remote - SSH 插件 → F1 → Remote-SSH: Connect to Host → nvidia@<Jetson的IP>
```

### 1.3 传输文件（Windows ↔ Jetson）

```powershell
# Windows PowerShell 里执行：

# 传"单个文件"到 Jetson
scp C:\路径\文件.py nvidia@<Jetson的IP>:~/Desktop/TL/TL_Handback/src/tl_hand/tl_hand/

# 传"整个文件夹"到 Jetson（推荐：整体同步 TL 工程）
scp -r C:\Users\DragonAfterAll\Desktop\TL nvidia@<Jetson的IP>:~/Desktop/

# 从 Jetson 拉文件回 Windows
scp nvidia@<Jetson的IP>:~/tl_mock_pick_place/basket_aruco.yaml C:\Users\DragonAfterAll\Desktop\
```

### 1.4 登录后的第一步：认识环境


## 第二章 终端分工（操作前先开好窗口）

**标准三终端布局**（SSH 连上后开 3 个会话，MobaXterm 里右键复制标签页即可）：

| 终端 | 用途 | 常驻性 |
|---|---|---|
| **终端 A** | 机械臂驱动 | 全程常驻，最先起/最后关 |
| **终端 B** | 业务程序（示教/种子节点/叉子节点，三选一）| 按需 |
| **终端 C** | MQTT 发命令/看反馈 | 按需 |

**总纪律**：
1. 驱动最先启动、最后关闭
2. 标定 / 示教 / 运行 **互斥**——同一时间只有一个程序控制机械臂
3. 物理急停按钮始终在手边
4. 每个新 SSH 终端都是干净环境，**脚本会自动处理**（本项目脚本都自带环境加载）
5. **不要新旧混跑**：同一条链路（种子/叉子）同一时间只跑一个程序；**A3 排与下排盆的脚本用新版**（`TL_lowerobs_test`），其余盆两版兼容

## 第四章 手眼标定（需要重标定时才做，终端 B）

> 触发条件：新装相机/支架变动/换机械臂/标定质量存疑。日常操作**跳过本章**。

### 4.1 采集
```bash
bash ~/Desktop/TL/TL_Dobot/scripts/run_handeye_collect.sh
```
- **驱动必须先在跑**（终端 A）
- 棋盘格：9×6 内角点（方格 25mm），贴刚性平板固定
- 操作：拖拽机械臂 → 让棋盘格完整入镜 → 松开拖拽键 → **静止 2-3 秒** → **鼠标点一下预览窗口** → 按 `s`

- 窗口左上角 `board=OK` 才能按 s；按 `q` 退出

### 4.2 求解
```bash

bash ~/Desktop/TL/TL_Dobot/scripts/run_handeye_calibrate.sh ~/tl_handeye_data/session_XXXXXXXX_XXXXXX
echo "exit_code=$?"          # 0 = 通过
```

### 4.3 部署
```bash
cp ~/tl_handeye_data/session_xxx/calibration/handeye_accepted.yaml \
   ~/tl_handeye_data/best/handeye_best.yaml

```

### 4.4 九点验证

```bash
  ~/tl_handeye_data/best/handeye_best.yaml
```

**通过标准**：exit_code=0、XY RMS ≤5mm、最大 ≤8mm。

```bash
     ~/tl_mock_pick_place/archive/basket_aruco_$(date +%Y%m%d_%H%M%S).yaml
```

### 6.2 启动
```bash
# 上排盆（A2/B2/B3，不含 A3）→ 老版：
bash ~/Desktop/TL/scripts/teach_seed.sh
# A3 排 + 下排盆（A1/A4/B1/B4）→ 必须用新版：
bash ~/Desktop/TL_lowerobs_test/scripts/teach_seed.sh
```
**启动确认**：
1. `marker black-square length=54.0 mm`
2. 自动回 A 侧起始位（机械臂开始缓慢运动）
3. `complete=[...]` 进度列表
4. （新版）`Reversed-row code mapping active: ['A3'] ...` ← A3 贴反修正生效的标志

### 6.3 每盆操作（核心流程）

```
【第 1 步】拖到检测位
  按住机械臂末端 P 键拖动 → 让目标花盆的码清晰完整入镜
  条件：码在画面中央附近、四周带白边、距离 30-50cm、无反光阴影
  稳住 2-3 秒，看预览窗口 visible=[...] 里出现目标号

【第 2 步】输入编号 → 按 B
  键盘依次按数字（如 29；A3 排按"物理第几格"输，程序自动换算）
  按 B
  ★ 必须看到 "Selected basket number=29"（号=你输的号）
  ★ A3 排按 B 时会先打印 "Reversed-row mapping: position number 56 -> actual code number 65 (ID64)"
    （没有这行 = 用的是老版程序，A3 别用它教）
  ✗ 报 "not visible / stable samples" → 重新对准+稳住，重按 B

【第 3 步】拖到接近位 → 按 A
  拖到花盆正上方（盆沿上方约一手掌高度）
  按 A → 看到 "Saved basket_approach for marker numbers [29]"

【第 4 步】降下去到释放位 → 按 P
  ★ 按住 P 键把手往下拖，进盆口到种子落下的位置
  按 P
  ★ 必须看到 "basket_release is XX mm below basket_approach"（XX 为正数）
  ✗ 显示 "0 mm below" → 没降下去，重做第 4 步

【第 5 步】按 R 返回 → 教下一盆
```

> **下排盆（A1/A4/B1/B4）额外前置（新版）**：先记录一次"下排观测位"——
> 拖到能看清下排码处（按 `v` 可确认/切换当前侧，看打印 `Current side:`）→ 停稳 1~2 秒 →
> 按 `d`（核对打印 `side=A`）→ 按 `g` 验证。**B 侧不必记录**（运行端自动按 A 侧+180° 推导）。
> 没记录之前跑下排盆会直接报错。

### 6.4 A / B 区域切换

| 区域 | 编号 | 机械臂朝向 | 切换方式 |
|---|---|---|---|
| A 区（A1-A4 排）| 1~96 | J1 ≈ -83° | 启动默认在 A 侧 |
| B 区（B1-B4 排）| 97~192 | J1 ≈ +96° | **按 `v`** 自动转过去 |

- B 区编号是三位数：B1-01=97、B2-05=125、B4-24=192
- **防错机制**：如果在 A 侧输入 97 按 B，会报 `not visible`——按 v 转过去再按
- **A3 排（49~72）**：该排的码当初被贴反了（第 1 格上贴的是 ID71），已用软件修正——**按"第几格"输编号即可**（如教 A3-08 就输 56），程序自动换算；已教的两盆现在叫 **A3-17 / A3-11**

### 6.5 其他按键
| 键 | 功能 |
|---|---|
| `c` | 清空输入缓冲（输错号时用）|
| `v` | 切 A/B 侧（去该侧起始位）|
| `d` | 记录"当前侧下排观测位"（拖到位停稳再按；**只有新版有**）|
| `g` | 回到当前侧下排观测位（验证用；**只有新版有**）|
| `R` | 自动返回当前盆检测位 |
| `Q` / `Esc` | 退出（数据已实时保存）|

### 7.2 发命令（终端 C）
```bash
# 订阅反馈（先挂上）
mosquitto_sub -h 116.205.245.172 -u shapandevice -P 'qwer1234!!' \
  -t node/arm/01/up -q 1 -v

# 另开一个终端 C2 发命令：
# A 区放种（A2-01 = 25 号）
mosquitto_pub -h 116.205.245.172 -u shapandevice -P 'qwer1234!!' \
  -t node/arm/01/down -m '{"cmd":"seed","targetId":"A2-01"}' -q 1

# B 区放种（B1-01 = 97 号；必须先教过）
mosquitto_pub -h 116.205.245.172 -u shapandevice -P 'qwer1234!!' \
  -t node/arm/01/down -m '{"cmd":"seed","targetId":"B1-01"}' -q 1

# A3 排（码贴反已修正；已教两点现在用 A3-17 / A3-11，旧写法 A3-08 / A3-14 已失效）
mosquitto_pub -h 116.205.245.172 -u shapandevice -P 'qwer1234!!' \
  -t node/arm/01/down -m '{"cmd":"seed","targetId":"A3-17"}' -q 1
```

### 7.3 反馈判读（一条命令回 4 条）
```
{"cmd":"seed","targetId":"A2-01","retCode":1}         ← ① 收到命令，开始取种
{"cmd":"seed","targetId":"A2-01","retCode":0}         ← ② 取种完成
{"cmd":"seed_place","targetId":"A2-01","retCode":1}   ← ③ 放置响应（识别成功）
{"cmd":"seed_place","targetId":"A2-01","retCode":0}   ← ④ 放置完成 ✓
```

| 异常反馈 | 含义 | 处理 |
|---|---|---|
| `retCode:3 ... "not fully taught"` | 目标没示教 | 先示教该盆 |
| `retCode:3 ... "not visible"` | 现场识码失败 | 检查码、光照、花盆位置 |
| `retCode:2` | 忙（上一条没完成）| 等周期结束再发 |
| 取种阶段 `seed:3` | 抓取失败 | 看 message（手状态/IK 等）|
| 放置阶段 `seed_place:3` | 放置失败 | 看 message（偏移超限/IK 等）|

### 7.4 急停
```bash
mosquitto_pub -h 116.205.245.172 -u shapandevice -P 'qwer1234!!' \
  -t node/arm/01/down -m '{"cmd":"estop"}' -q 1
```
⚠️ 急停后**锁存**：所有命令被拒，需**重启节点**恢复。物理急停按钮始终是最后保障。

## 第八章 叉子示教与运行（修剪任务，与播种互斥）

### 8.1 叉子示教（统一用新版）
```bash
bash ~/Desktop/TL_lowerobs_test/scripts/teach_fork.sh
# 启动不动臂；只有 O / v / g / R 会自己动，其余靠手拖
```

| 键 | 记录内容 |
|---|---|
| 编号 + `B` | 输花篮号（A3 排按"第几格"输，按 B 时自动换算并打印）→ 选定（锁码 + 记检索位）|
| `F` / `I` / `L` | 叉接近位 / 水平插入位 / 竖直抬起位（I、L 带校验，拖得不直会被拒，重新拖到位再按）|
| `W` / `T` | 高位载运点 / 暂放位（上排一对、下排另一对：教下排盆时按 W/T 自动存"下排专用"；第一盆要连教，以后不用重按）|
| `O` | 去**待机位**（= 种球默认位）并记录；**不是"看花篮"的位置** |
| `v` | 切 A/B 侧（去该侧起始位 `-83.668… / 96.332…`，教花篮的起点站位）|
| `d` / `g` | 记录 / 回到当前侧**下排观测位** |
| `R` | 回检索位（等打印 `Returned: max joint error=…` 才算走完）；`Q` 退出 |

流程：第一盆 `编号→B→F→I→L→W→T→R`；以后每盆 `编号→B→F→I→L→R`。
**修剪位 1/2 不用教**（写在程序里的固定值）。

### 8.2 叉子运行（用新版）
```bash
bash ~/Desktop/TL_lowerobs_test/scripts/run_fork_mqtt.sh    # 终端 B
# 命令（终端 C）：
mosquitto_pub -h 116.205.245.172 -u shapandevice -P 'qwer1234!!' \
  -t node/arm/01/down -m '{"cmd":"trim_pick","targetId":"A2-06"}' -q 1    # 叉走（停在修剪位2等剪根）
mosquitto_pub -h 116.205.245.172 -u shapandevice -P 'qwer1234!!' \
  -t node/arm/01/down -m '{"cmd":"trim_place","targetId":"A2-06"}' -q 1   # 放回原格
```
- `trim_pick` **只管叉走**（不自动放回）；剪完根再发 `trim_place`。
- 下排盆（A1/A4/B1/B4）会**先去对应侧下排观测位识别码**，再去叉取。
- 一直识别不到码会报 `retCode:3` 并**自动回待机位**（2026-10-07 起），排查后重发同一条命令即可。
- ⚠️ 叉上真有花篮时启动**不会自动动**（`active_transfer.yaml` 保护），先发 `trim_place` 放回；确认叉子为空才可 `rm ~/tl_fork_teach/active_transfer.yaml`。

## 第十章 常见问题速查

| 现象 | 排查 |
|---|---|

## 第十一章 安全须知（必读）

1. **物理 E-stop 始终在手边**——程序级 estop 只停运动流，不是断电
2. 机械臂运动路径上**禁止站人**；首次跑新姿态用慢速+旁观
3. **九点验证通过前禁止灵巧手自动闭合与接触抓取**

5. 示教/运行中确认码贴正、花盆固定
6. 公网 MQTT 凭据不要外泄
7. 急停锁存是保护设计——**重启节点**才恢复，不要试图绕过
8. **动作没走完不要按 Ctrl+C**（等 `Arrived:` / `Returned: max joint error=…` 打印完再操作）；中断搬运后重启程序发 `trim_place` 收尾
