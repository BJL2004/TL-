# 大模型控制天链机械臂演示（TL / MQTT 版）— 说明与运行手册

> 目标：本地大模型（Ollama，默认 phi3:mini）听懂中文 → 输出 JSON 指令 → 白名单+编号校验 → MQTT → **你原有的程序执行，一行不改**。
> 用的是你 TL_lowerobs_test 现成的协议：`node/arm/01/down`（命令）/ `node/arm/01/up`（反馈）。
>
> **与 Dobot 版的区别**：Dobot 版大模型生成的是坐标（要靠安全层限幅）；TL 版大模型只生成"语义指令"（取哪盆、放哪盆、种哪盆），**运动安全完全由你原有程序负责**——所以风险更小、更简单。

---

## 一、原理（数据流）

```
你打字: "修剪A3第11号"
      │
      ▼
Ollama (http://127.0.0.1:11434, 默认 phi3:mini)    ← 本地大模型
      │  {"cmd":"trim_pick","targetId":"A3-11"}
      ▼
llm_tl_agent.py  校验层
      │  · 白名单: trim_pick / trim_place / seed / estop
      │  · 编号归一化: "A3 第11号"→"A3-11", "B1第1号"→"B1-01", 行A1~B4×01~24
      │  · 非法直接拒绝    · 发送前需按 y 确认
      ▼
MQTT 发布 node/arm/01/down
      │
      ▼
Nano 上你原有的程序 (run_seed_mqtt.sh / run_fork_mqtt.sh)  → 机械臂执行
      │
      ▲ 反馈 node/arm/01/up: retCode 1=开始动作 → 0=成功 / 2=忙碌 / 3=失败
```

## 二、目录内容

| 文件 | 作用 |

## 三、前提

1. **Nano 端**：对应程序在运行——取花/放回用 `scripts/run_fork_mqtt.sh`，播种用 `scripts/run_seed_mqtt.sh`（**只有一种任务时别同时开两个**，它们抢同一对主题）
2. **Windows 端**：Ollama 已运行 + `phi3:mini` 模型（你已有）；`paho-mqtt` 已装（已装好 2.1.0）
3. 网络：Windows 能访问 116.205.245.172:1883（普通网络即可）

## 四、运行步骤

全部命令在 `C:\Users\DragonAfterAll\Desktop\TL_LLM_demo` 下执行。

### 第 0 步：只测大模型（不连 broker）

```bash
python llm_tl_agent.py --llm-only "修剪A3第11号"
# → [将发送] {"cmd":"trim_pick","targetId":"A3-11"}   # 取花(修剪) A3-11
```

### 第 1 步：broker 只读自检

```bash
python llm_tl_agent.py --check
```

只连接+订阅，**不发任何命令**。看到 `[OK] broker 连接成功` 即可。

### 第 2 步：试运行（连 broker，翻译给你看，但不发送）

```bash
python llm_tl_agent.py
```

### 第 3 步：真实发送（Nano 端程序已运行时）

```bash
python llm_tl_agent.py --execute
```

- 每条命令发送前要按 `y` 确认；演示流畅可加 `--yes`（第一次别加）
- 发送后会实时显示反馈：`⏳ 已开始动作` → `✅ 完成 (retCode=0)` 或 `❌ 失败`
- 20 秒内没有任何反馈会提示"Nano 端程序是否在运行"

### 语音模式（🎤 说中文直接控制）

```bash
python llm_tl_agent.py --execute --voice     # 语音+真实发送
python llm_tl_agent.py --voice               # 语音+试运行(不发)
```

- **按回车开始说话，说完停顿自动结束**，识别文本走同一条大模型管线；
- 识别提示词已偏向园艺词汇（修剪/播种/花盆编号），说"A3 第11号"这类更准；
- 参数：`--init-voice` 列麦克风；`--stt-model` small(默认)/base(快)/medium(准)；`--stt-device cpu`(默认)；
- 说完 → 识别约 1~2 秒 → 大模型约 0.3 秒 → 显示 MQTT 指令 → `y` 确认发送。

## 五、演示台词（全部实测通过）

| 你说 | 发送的指令 |
|------|-----------|
| 修剪A3第11号 / 摘A4-24 | `trim_pick A3-11` / `trim_pick A4-24` |
| 把B1第1号的花放回去 | `trim_place B1-01`（个位数自动补零） |
| 给A1第5号播种 | `seed A1-05` |
| 急停 / 停下 | `estop`（无编号，立即停止运动流） |
| 你好呀 | 不动作（`none`，直接拒绝） |

> 换模型对比：`--model deepseek-r1:1.5b`（不推荐，实测会抄错示例）或 `--model llama3.2:1b`。默认 phi3:mini 最稳。

## 六、安全设计

1. **白名单**：只有 4 种指令 + none；模型生成其它内容一律不执行；
2. **编号归一化校验**：`A3 第11号` → `A3-11`（两位补齐）；非 A1~B4×01~24 一律拒绝——模型写错编号也发不出去；
3. **逐条确认**：默认每步按 y；
4. **estop 语义**：说"停下/急停"→ estop 指令。注意：**这是程序化急停（锁存，需在 Nano 端重启对应程序解锁），不是断电**；真正的紧急情况请按物理急停；确认键就是防止误触发锁存；
5. **不碰运动参数**：速度、轨迹、安全全由你原有程序控制，本程序只发指令；
6. **A3 反向贴码**：由你原有程序处理（4 个脚本默认 `--reversed-rows A3`），本程序只管发标准编号。

## 八、故障排查

| 现象 | 原因 | 解决 |
|------|------|------|
| `broker 拒绝连接` | 用户名/密码/网络 | 检查网络能否访问 116.205.245.172:1883 |
| 发送后 20s 无反馈 | Nano 端程序没在运行 | 在 Nano 上启动 `run_fork_mqtt.sh` / `run_seed_mqtt.sh` |
| `retCode=2 位置被占用/忙碌` | 上一任务未完成/花盆已有花 | 等完成后重试 |
| `retCode=3 识别/放置失败` | 识别不成功、编号未示教 | 检查目标是否已示教（`list_taught.py`） |
| `[解析失败]` | 小模型偶发 | 已内置自动重试一次；换说法再试 |
| estop 后机械臂不动了 | 急停锁存 | 在 Nano 端 RESTART 对应程序解锁 |
| 🎤 `没有检测到说话声` | 声音小/离麦远 | 靠麦克风近一点、正常音量再说一次 |
| 🎤 `打不开麦克风` | 设备被占用/序号不对 | `--init-voice` 看设备列表 |
| 🎤 识别错词（编号听错） | 小模型听感 | 换 `--stt-model medium`；说话时把"A3 杠 11"念清楚 |
| 语音模式启动报 OMP 错误 | Anaconda MKL 冲突 | 已在 voice_stt.py 自动规避；仍报错换干净终端 |

## 九、演示流程建议（2 分钟版）

1. Nano 上 `run_fork_mqtt.sh` 已运行；Windows 上 `--check` 通过；
2. `--execute` 启动；
3. 说"修剪 A3 第 11 号" → `y` → 屏幕显示 `⏳ 已开始动作` → `✅ 完成`；
4. 说"把 A3-11 的花放回去" → `y` → 完成；
5. 说"你好呀" → 显示"非动作"，说明它不会乱执行；
6. 结束（`exit`）。

> 演示时把"模型原始输出"那行指给别人看——"看，这是大模型现场生成的 JSON 指令，不是我写死的"。
