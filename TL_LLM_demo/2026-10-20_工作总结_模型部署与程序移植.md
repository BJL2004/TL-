## 1. 部署的模型（Ollama，板上运行）

### 1.1 phi3:mini —— LLM（指令解析，主力）

| 项 | 内容 |
|---|---|
| 模型 | `phi3:mini`（微软 Phi-3 mini，3.8B 参数，Q4 量化约 2.3GB） |
| 部署位置 | 开发板上 Ollama（`http://127.0.0.1:11434`），GPU 推理 |
| 用途 | 把现场中文指令翻译成任务级 JSON，例如：`{"cmd":"seed","targetId":"A3-17"}` |
| 调用方式 | `/api/chat`，`format=json`，温度 0.1，系统提示词 + 8 条 few-shot |
| 支持的两种说法 | ① 编号式：`把种子放到 A3-17` ② 序号式：`把种子放到第三排第十七盆`（排1-4→A1-A4，排5-8→B1-B4，盆1-24） |
| 输出约束 | 只允许 `cmd ∈ {seed, seed_place, trim_pick, trim_place, estop}` + `targetId`（`A1-01 ~ B4-24`）；**绝不输出坐标/轨迹/速度** |

### 1.2 qwen2.5vl:3b —— VLM（视觉辅助，仅报告不决策）

| 项 | 内容 |
|---|---|
| 模型 | `qwen2.5vl:3b`（多模态，约 3.2GB） |
| 部署位置 | 同上，板上 Ollama（GPU） |
| 用途 | 抓放过程中的**视觉复核辅助**：看 TL 观测位画面，报告二维码是否清晰/被遮挡/异常 |
| 取图方式 | TL 程序在观测位检测时把最新帧存到 `~/tl_llm_agent/frames/latest.jpg`（见 3.3 补丁），VLM 读这个快照 |
| 触发时机 | ① 每次任务回执返回后自动复核（识码失败 retCode=3 时重点提示）② 交互输入 `看一眼` 手动复核 |
| 局限（实测验证） | 3B 模型判断会自相矛盾（同一张图"没有二维码"又说"二维码清晰"）→ **只做辅助报告，不参与动作决策**；快照超过 180 秒视为过期不用 |

### 1.3 板上部署命令（JetPack 6 原生支持 Jetson CUDA）

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull phi3:mini        # ~2.3GB
ollama pull qwen2.5vl:3b     # ~3.2GB
ollama ps                    # 推理时确认 100% GPU；或 tegrastats 看 GR3D 占用
```

**注意**：
- JetPack 7.2 上 Ollama 预编译版会退回 CPU（缺 sm_87），**暂时不要升级系统**

- 若模型改跑其他机器：`--ollama-url http://<该机IP>:11434` 即可，代码不用改

## 3. TL_llm_agent 项目（TL TCB605 种子抓放 · 大模型 MQTT 控制）

### 3.1 方案与协议（沿用 TL 现有接口，不改变车端协议）

```
中文指令 → phi3:mini（Ollama）→ {"cmd":"seed","targetId":"A3-17"}
         → 安全层（白名单 + targetId 规则 + 规则×LLM 交叉核对 + 单任务互斥 + y/N + estop 直通）
         → MQTT node/arm/01/down → TL 现成算法执行（取种→识码→放置→回位）
         → 回执 node/arm/01/up → 人话报告 + VLM 视觉辅助复核
```

| 协议要素 | 值（与 TL 工程一致） |
|---|---|
| Broker | `116.205.245.172:1883`，账号 `shapandevice` / `qwer1234!!` |
| 主题 | 下行 `node/arm/01/down`；上行 `node/arm/01/up` |
| 命令 | `seed` / `seed_place` / `trim_pick` / `trim_place` / `estop` |
| targetId | 盆格编号 `A1-01 ~ B4-24`（2区×4排×24盆=192）；第1-4排=A1-A4，第5-8排=B1-B4 |
| retCode | 0 成功；seed: 1 失败、2 设备忙；trim: 1=已开始动作（非终态）、3=识码/放置失败 |

### 3.2 新程序 `TL_llm_agent/`

```
TL_llm_agent/
├── llm_tl_agent.py     ← 主程序（LLM + 安全层 + MQTT + VLM）
├── run_llm_agent.sh    ← 启动脚本（参数透传）
└── README.md           ← 部署/使用说明
```

核心功能：
- **两种说法都支持**：`A3-17` 编号式 + `第三排第十七盆` 序号式（序号转换同时用规则校验）
- **规则×LLM 交叉核对**：两种说法的目标盆由确定性规则再算一遍，与模型结果不一致 → **拒绝执行**（防 3.8B 模型算错排号）
- **安全层**：cmd 白名单、targetId 正则+范围、单任务互斥（等回执/超时）、y/N 确认、`estop` 免确认直通、默认 dry-run
- **VLM 视觉辅助**（见 3.3）：任务后自动复核 + `看一眼` 手动复核，只报告不决策
- 未收到回执时按 `--timeout`（默认 120s）报超时，不重复发送

### 3.3 修改的 TL 程序（VLM 快照钩子，共 2 个文件）

**目的**：TL 进程独占 RealSense（`start_camera()` 后全程占用）且不发 ROS 图像话题，VLM 无法独立取帧 → 在 TL 运行流程取帧处加"存一帧"钩子。

| 文件（Windows 副本） | 修改内容 |
|---|---|
| `TL_lowerobs_test/src/tl_hand/tl_hand/mock_pick_place.py` | 新增 `_save_vlm_frame(image)` 方法（约第 535 行）；两个取帧点（`_discover_visible_basket` 内 + 运行时识码采样循环内）各插入 5 行调用（try/except 包裹） |
| `TL/TL_Handback/src/tl_hand/tl_hand/mock_pick_place.py` | 同上（主 TL 运行代码，`run_seed_mqtt.sh` → `TL_Handback/scripts/run_fixed_pick_mqtt.sh` 加载） |

钩子行为：把当前帧写入 `~/tl_llm_agent/frames/latest.jpg` + `latest.json`（时间戳）。**仅写文件，不改变任何检测/放置逻辑，异常自动吞掉，绝不影响主流程。**

> 注意：修改后 **TL 程序必须重启**才会加载新代码；两个副本按实际跑的那份同步到板子即可（都同步最稳）。

  交互：输入指令 → 看解析 → y 确认 → 等回执 → 自动出视觉辅助报告；输入 `看一眼` 手动复核；`--no-vlm` 可关视觉辅助。

## 6. 风险与注意事项

1. **标定是"装夹快照"**：相机-末端装夹一动，标定全废（历史教训：会表现为"偏几厘米、方向随位置变"）。搬动后必须重标或用示教器对照法复验。
2. **两套系统 broker 不同**：Dobot 包（`192.168.38.213`）≠ TL（`116.205.245.172`），别混连。
3. **MQTT client-id 冲突**：TL 程序与测试客户端/新 agent 同跑时 client-id 必须不同（agent 已用随机 `llm-tl-agent-xxxx`）。
4. **TL 单任务互斥**：同一时间只能跑一个抓放任务（并发会回 retCode=2 设备忙）。
5. **可达性**：Dobot 抓取点水平距离 ≤ ~550mm（Nova2 臂展 625mm 留余量），超了会触发 `-2` 报警。
6. **JetPack 7.2 暂勿升级**：Ollama 预编译版在 JP7.2 上会退回 CPU（需要源码编译 sm_87）。
7. **3B VLM 只做辅助**：判断会摇摆/自相矛盾，关键判断以 TL 的 aruco 检测与人工为准。
8. **夹爪标签反转**（Dobot 版）：`set_gripper(False)`=打开、`set_gripper(True)`=关闭，脚本内个别打印文字与调用相反，以实际动作为准。
9. **TL 补丁仅写文件**：`_save_vlm_frame` 全程 try/except，若不需要视觉辅助，删除/不重启也无副作用；TL 两个仓库均有 git，可用 `git diff` 复核。
10. **回滚**：Dobot 包整体文件夹可删；TL 补丁可用 git checkout 还原；TL_llm_agent 文件夹可整体删除，不影响任何现有程序。

## 7. 2026-10-21 补充：Dobot Nova2 版按 TL 架构重构（LLM 只动嘴）

### 7.1 重构目标与结果

按 TL TCB605 版同一套原则改造 Dobot 版：

```
大模型只动嘴（翻译） → 安全层把关（确定性规则） → 执行层干活（YOLO 抓取算法） → VLM 只当参谋
```

- LLM（phi3:mini）只输出**任务级命令**：`grasp / place / pick_place / estop` + 颜色；

- VLM（qwen2.5vl:3b）只读执行端保存的画面做报告，**不参与指令解析、不改变动作**。

### 7.3 协议映射（执行层协议不变，只是被 LLM 调用）

| 意图 | 下行 MQTT | 回执 |
|---|---|---|
| 抓红/蓝/绿/黄 | `{"taskid":"...","color":"red|blue|green|yellow"}` | `result_code` 0~11/99 |
| 放置 | `{"taskid":"...","place":1}` | 同上 |
| 急停 | `{"taskid":"...","cmd":"estop"}` | `result_code=0` |
| 抓+放 | 先抓（等 0）→ 再放置（新 taskid） | 两步各一条 |

### 7.4 安全层规则（确定性，已自检）

1. cmd 白名单 + 颜色白名单；
2. 规则解析与 LLM 解析**颜色不一致 → 拒绝**；
3. 缺颜色、没说动作、只说颜色、有颜色但动作不明（如“红色方块放到放置点”“把红色放下”）→ 拒绝，不猜；
   （规则层独立判定，即使 LLM 猜出 grasp/pick_place 也不放行）
4. 默认 dry-run；实跑逐条 `[y/N]`；单任务串行；
5. 执行层再兜底：持有状态互斥（已持有抓=11，空手放=9）、颜色非法=7；
6. VLM 结果不回流到命令解析；
7. 物理急停优先；MQTT estop 只停当前运动（agent 等回执期间无法输入急停，真机手不离急停）。
